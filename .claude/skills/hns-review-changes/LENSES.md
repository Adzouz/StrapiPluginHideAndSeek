# Lenses

What a reviewing subagent reads the diff through. The parent of `hns-review-changes` hands this file and a set of zone ids to every subagent it briefs, and never applies a row itself. Read every row of every zone you were handed, then `## Seams`, `## Always on` and `## Risk signals`. A check you skipped needs its reason in your satellite: a lens silently dropped is coverage the overview will claim and the run never had.

**A row is a question and a place to look, never an answer.** It names the property of this plugin — or of the Strapi it is a guest inside — that makes a class of change dangerous. Go read the code. A finding anchored to this file rather than to the tree is not a finding.

## Seams

What a per-file partition cannot see, because the mechanism lives between two files different shards own. The cross-cutting shard reads this section; every other shard reads it too, and returns a seam it crossed as a candidate rather than assuming the other shard has it.

- **One page string, four readers.** The browser reports a path; the engine stores it as a room, the hint system points at it, the deletion guard parses ids out of it, and the overlay renders it. A change to what a page _is_ lands in all four, and the guard is the one that fails silently.
- **The engine's state shape is the client's contract.** `publicState()` is the only thing the admin sees. A field renamed, newly nullable, or no longer sent is a UI bug one file away with nothing to catch it.
- **Lobby settings and config defaults meet in the clamp.** A ceiling enforced on one path and not the other is no ceiling.
- **The guard runs before auth; the game knows who everyone is.** Everything the guard says is derived from authenticated state but spoken to an unauthenticated caller. That asymmetry is the plugin's main information-disclosure surface.
- **Ticket, socket and admin session are three different clocks.** A round outliving the admin session, or a ticket outliving its single use, each breaks a different guarantee.
- **The overlay lives outside React's tree and Strapi's router.** It survives navigations that unmount everything else, which is the point and also how it strands state.

## Always on

Independent of zone, on every changed file.

- **Translation coverage** — a new string with no key, or a key missing from a catalogue. Rank `convention`, or `correctness` when the untranslated string is the only explanation the user gets.
- **Teardown** — every `setInterval`, `setTimeout`, `addEventListener`, socket handler, DOM node and React root created has a matching removal on the path that ends its life. Rank `correctness`.
- **Unbounded growth** — a `Map`, array or event list that only ever gains entries. Rank `correctness`.
- **Leaked secrets and fixtures** — real hostnames, tokens, or the test admin credentials in committed code. Rank `security`.
- **Logging** — anything written at 20Hz, or a log line carrying a token, an email or a query string. Rank `convention`, `security` for the second.
- **Style follows the file** — this repo's comments explain _why_ in full sentences and the formatting is Prettier's. A change that reads like a different author is a `convention` finding only if it actually diverges, never as a matter of taste.

## Risk signals

Where a small diff has process-wide or user-visible consequence. Each signal fixes the **rank**; `disposition` stays the finder's call, anchored like everything else.

**Pre-authentication surface** — rank `security`. Anything the deletion guard, or any other `strapi.server.use()` middleware, says or does before Strapi's router has authenticated the caller. New information in a refusal body, a new route matched, or a new reason to answer rather than pass through.

**Host process stability** — rank `correctness`, `merge-blocker` unless the diff shows the throw is contained. The tick, the socket handlers and the bootstrap all run inside the customer's Strapi. An uncaught throw takes down their CMS, not this plugin.

**Breaking contracts** — rank `breaking`, `merge-blocker` when the same diff ships no note in the CHANGELOG. What counts, because the consumer lives outside this repo:

- the `./strapi-admin` / `./strapi-server` exports and the published `files` list
- the 409 refusal shape — status, `error.name`, `error.details` keys — which API clients parse
- which requests are refused mid-round, since that is an API behaviour change for every integration
- plugin config keys, their types and their defaults
- the minimum Strapi version any new API implies

**Trusting the client** — rank `security`. Server behaviour newly keyed on a value the browser supplies: page, cursor, visibility, timing, or a claim about a previous session. Ask what a player with a console does with it.

**Denial of service by configuration** — rank `security`. A setting that, at its extreme, holds the deletion guards armed, keeps admin sessions alive, or pins memory. Unbounded is the finding; the ceiling is the fix.

**Silent player loss** — rank `correctness`. A player who ends a round stranded, invisible, uncatchable, frozen, or credited with something they did not do. This plugin's bugs mostly look like this, and they are invisible to every automated check in the repo.

## Test expectations

The evidence a change of each kind owes. Missing it is a `test-docs` finding unless the satellite gives the concrete reason it does not apply.

| Change                                      | Expected evidence                                                                          |
| ------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Engine rule, phase transition, clamp        | a case in `tests/unit/game.test.mjs` that fails before the fix                             |
| Request matcher in the deletion guard       | a case in `tests/unit/protect-players.test.mjs`, including the encoded and malformed forms |
| Config key, type or ceiling                 | a case in `tests/unit/config.test.mjs`                                                     |
| Anything involving folder or entry identity | a fixture where the two identifier spaces **differ**, or it proves nothing                 |
| Socket lifecycle, reconnect, multi-tab      | the live suite that covers it, named — and stated as not run, since CI never runs them     |
| Overlay or widget behaviour                 | no harness exists; say so in `runtime` rather than implying coverage                       |

## Keeping this file

Add a row's worth of design, never a line of implementation. Before adding anything, ask whether it would still be true after a refactor that preserved behaviour. A private function name, a constant, a line number, or a bug that exists today all fail that test: they belong in the review that found them, or in the fix. What belongs here is the shape of the system that makes a class of change dangerous, and the shortest path to reading the current truth.
